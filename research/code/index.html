Commit to the specific program

A program can look like a familiar pattern and behave differently in a detail that matters. A prediction made before execution gives the experiment something concrete to check. The experiment compares the recorded prediction with the observed output.

The local research corpus contains Python and JavaScript cases, with buggy functions and corresponding corrected versions. The aim is to probe particular reasoning failures rather than infer broad coding ability from a small collection.

A familiar operation, a different meaning

The argument to strip is a set of characters to remove from both ends. It is not a suffix to remove as a unit. A plausible explanation of “string cleanup” can miss the behavior of this exact call.

Other cases examine mutation versus returned values, late-bound closures, empty-input behavior, floating-point comparison, and language-version changes.

Execution, symbolic checks, and scope

The execution harness supplies the reference behavior. A separate AST-based symbolic layer recognizes a limited set of patterns and explicitly declines cases outside its scope. Declining a case is different from finding it correct.

Exact output matching can also turn an interpreter error-message change into a miss. Version-dependent cases therefore need an explicit runtime version and an explanation of what changed.

What the corpus does not establish

This is a small experimental corpus, not a general coding benchmark. The local adapter for paid model calls has not been used for a paid model evaluation. Hand-recorded predictions, symbolic checks, and model results must not be combined into one headline model score.

The corpus is not yet publicly released. The broader connection to physical reasoning is a shared question about applying a rule outside the conditions that make it valid.
